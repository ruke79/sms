> **사용법**: 키워드만 보고 일본어로 말할 수 있으면 실전 가능선. 원문은 [`../db-면접/`](../db-면접/README.md).

# Part 1. 인덱스·트랜잭션·커넥션 (Q1~25)

| Q | 질문 | 키워드 |
|---|---|---|
| 1 | 정규화 vs 비정규화 | 먼저 정규화 · **측정 후 조인이 병목일 때만** 비정규화 · 갱신 경로 하나로 · 처음부터 비정규화 = 이른 최적화 |
| 2 | 기본키 선택 | 불변·무의미 · 업무값 PK 는 사양 변경에 깨짐 · 자동 채번은 건수 노출 · **UUID v4 는 삽입 흩어짐 → v7** ✅`DB-05` |
| 3 | 인덱스 구조 | B+트리 · 로그 시간 · 범위·정렬에 효과 · **쓰기가 느려짐** → 전 컬럼 인덱스는 역효과 |
| 4 🔴 | 인덱스가 안 쓰이는 경우 | 컬럼 가공 · 중간 일치 · **선택도 나빠 전건이 빠르다고 판단**(정상 동작) · 실행 계획에서 이유 확인 ✅`DB-03` |
| 5 🔴 | 복합 인덱스 컬럼 순서 | **선행 컬럼부터만** · `(A,B)` 는 B 단독 불가 · 등치 앞 / 범위 뒤 · 정렬까지 포함하면 소트 생략 ✅`DB-14` |
| 6 | 커버링 인덱스 | **테이블 본체를 안 읽음** · 랜덤 액세스 제거 · `INCLUDE` · 컬럼 늘면 쓰기·캐시 악화 → 효과 큰 쿼리만 |
| 7 🔴 | 실행 계획에서 보는 것 | 접근 방법 → 조인 방법·순서 → **추정 행 수 vs 실제 행 수** · 통계 낡음 · `EXPLAIN ANALYZE` ✅`DB-03` |
| 8 | 조인 알고리즘 | 네스티드 루프/해시/머지 · 작고 인덱스 있으면 NL · 큰 것끼리 해시 · 정렬돼 있으면 머지 · **행 수 추정에서 역산** |
| 9 | 통계 정보 | 옵티마이저의 행 수 추정 근거 · 낡으면 나쁜 계획 · **대량 적재 직후 명시적 갱신** |
| 10 | ACID | 원자성·일관성·독립성·지속성 · **실무 논쟁은 독립성** · 완화된 격리 수준 기본 |
| 11 🔴 | 격리 수준을 현상으로 | RC: 반복 불가능 읽기 · RR: 스냅샷 유지 · SERIALIZABLE: 경합 시 실패 → **재시도 전제** · PG/MySQL 기본값 다름 ✅`DB-01` |
| 12 🔴 | MVCC | 행의 여러 버전 · **읽기가 쓰기를 막지 않음** · 옛 버전 누적 → VACUUM · **긴 트랜잭션이 테이블 부풀림** |
| 13 | 스냅샷 격리로 못 막는 것 | **쓰기 스큐** · "당직 최소 1명" 깨짐 · SERIALIZABLE/명시적 락/DB 제약 · 앱 조건 분기만으론 불가 ✅`DB-09` |
| 14 | 락 종류 | 행/테이블 · 공유/배타 · InnoDB **갭 락** · **쥐는 시간을 짧게** — 트랜잭션 안 외부 API 금지 |
| 15 🔴 | 데드락 | **접근 순서 통일** · 짧게 · 재시도 전제 · **0 불가능** · 로그에서 얽힌 문장 확인 ✅`DB-07` |
| 16 | 낙관 락 vs 비관 락 | 경합 적음 → 버전 컬럼 · 경합 많고 실패 비용 큼 → `FOR UPDATE` · **비관 락은 타임아웃 필수** ✅`JPA-04`·`JPA-07` |
| 17 🔴 | 커넥션 풀 사이즈 | **크게 잡아도 안 빨라짐**(대기열이 DB 안으로) · 코어 수의 몇 배에서 출발 · **인스턴스 수 × 풀 ≤ DB 상한** ✅`DB-02` |
| 18 🔴 | 풀 고갈 원인 판별 | 누수/장시간 점유/용량 부족 · **부하 멈춘 뒤 active 안 줄면 누수** · 부하 중에만 → 점유·용량 ✅`DB-06` |
| 19 🔴 | SQL 인젝션 | 파라미터 바인딩 · 이스케이프는 누락 생김 · **바인딩 불가 자리(테이블명·정렬 컬럼) → 화이트리스트** ✅`DB-04`·`DB-19` |
| 20 | 페이징 | `OFFSET` 은 뒤로 갈수록 느림 + 중복·누락 · **키셋 페이징** `WHERE (created_at,id) < (?,?)` · 임의 페이지 점프만 OFFSET |
| 21 | 건수 취득이 무거울 때 | **정확한 수가 정말 필요한가** · "다음 페이지 있나"는 한 건 더 가져오기 · 통계 추정 · 카운터 테이블 |
| 22 | 대량 삽입 | 배치로 왕복 감소(자릿수 차이) · 벌크 로드 · 인덱스·제약 잠시 해제 · **재개 지점 설계** ✅`PERF-11A` |
| 23 | 일괄 갱신·삭제 | 나눠서 · 대량 삭제는 옛 버전 누적 → 논리 삭제/파티션 분리 · **ORM 벌크는 영속성 컨텍스트 우회** |
| 24 | 느린 쿼리 찾기 | 슬로 로그 · `pg_stat_statements` · **한 번 느린 것 vs 횟수 많아 합계로 무거운 것** · 총 시간 내림차순 |
| 25 | 앱 N+1 | **쿼리 횟수를 센다**(시간 아님) · 조인/묶음 별도 쿼리 · 페이징 얽히면 ID 모아 `IN` · 고친 뒤 **다시 센다** ✅`JPA-01` |

# Part 2. 확장·운영·설계 (Q26~50)

| Q | 질문 | 키워드 |
|---|---|---|
| 26 | 파티셔닝 목적 | 조건에 맞는 파티션만 읽기 · 날짜 · 오래된 것 파티션째 삭제 · **키가 조건에 없으면 전 파티션 → 오히려 느림** ✅`DB-08` |
| 27 | 샤딩 vs 파티셔닝 | 한 DB 안 vs 여러 서버 · 샤딩은 쓰기 확장되지만 **크로스 샤드 조인·트랜잭션 불가** · 레플리카·파티션 먼저 · 샤드 키 변경이 가장 비쌈 |
| 28 | 리드 레플리카 주의 | 복제 지연 · **"자기가 쓴 것을 읽는" 경로는 프라이머리** · 지연 모니터링 + 임계 초과 시 되돌리기 ✅`DB-24` |
| 29 | 무중단 스키마 변경 | **추가 → 양쪽 쓰기 → 이행 → 읽기 전환 → 삭제** · 신·구 코드 동시 실행 조건 · **타입 변경은 테이블 재작성** · 메타데이터만인지 확인 ✅`DB-11`·`MSA-05` |
| 30 | 스키마 변경 관리 | 마이그레이션 도구 · 코드와 같은 저장소 · **전진뿐**(되돌리기는 상쇄 마이그레이션) · ORM 자동 갱신 운영 금지 |
| 31 | 백업·복구 | RPO/RTO 에서 결정 · 시점 복구 · **복구를 실제로 해 본다**(복원 훈련) · 다른 장소 |
| 32 | DB 모니터링 | 접속·대기·느린 쿼리·복제 지연·디스크·캐시 히트율 · PG 는 장시간 트랜잭션·VACUUM · **평균 아닌 분포·추세(p99)** |
| 33 | 캐시 위치·방식 | 읽기 많고 낡아도 되는 곳 · 캐시 어사이드 · 무효화가 어려움 → 갱신 경로 하나 · **캐시 전에 쿼리 자체를 빠르게** |
| 34 | 캐시 스탬피드 | 만료 순간 DB 로 몰림 · 재계산 하나로 묶기(락) · 만료 시각 지터 · 만료 전 비동기 갱신 |
| 35 🔴 | 두 번 실행돼도 괜찮게 | 멱등 · 요청별 고유 키 + **유니크 제약** · 앱에서 "이미 처리했나" 확인은 **동시에 오면 둘 다 통과** · 최종 보증은 DB 제약 ✅`DB-12` |
| 36 | 분산 락만으로 충분한가 | 불충분 · 만료 후 이전 소유자가 덮어씀 · **펜싱 토큰**(단조 증가, 쓰는 쪽이 옛 번호 거절) · 락은 효율, 정확성은 쓰는 쪽 ✅`DB-16` |
| 37 | DB 갱신 + 메시지 발행 일치 | 한 트랜잭션 불가 → **Outbox** · 같은 트랜잭션에 발행 예정 기록 → 별도 프로세스 발행 · 받는 쪽 멱등 ✅`MSA-01` |
| 38 | CDC 주의점 | 앱 무수정 · **스키마가 그대로 하류로 → 결합 강화** · 삭제 이벤트에 PK 만 실리는 설정 · 순서·중복 전제 |
| 39 | 이벤트 소싱·CQRS | 감사·이력이 본질일 때 / 읽기·쓰기 요구 크게 다를 때 · 스키마 진화·재생 시간·결과적 일관성 · **경계 한정** · 스냅샷 |
| 40 | RDB vs NoSQL | 기본은 RDB(트랜잭션·제약·나중 질의 유연) · NoSQL 은 **접근 패턴이 명확할 때** · "확장되니까"만으로 고르면 조인에서 고생 |
| 41 | Redis 용도 | 캐시·세션·레이트 리밋·간단한 큐·정렬 집합 랭킹 · **영속화 설정 따라 데이터 소실** · 단일 스레드 → `KEYS` 금지 |
| 42 | 전문 검색 | **중간 일치는 인덱스 안 탐** · 형태소 분석 · 소규모는 DB 전문 검색 · 관련도·패싯 필요 시 검색 엔진(동기 지연·이중 관리 수용) |
| 43 | OLTP vs OLAP 분리 | 요구 정반대 · 같은 DB 면 분석이 업무 멈춤 · 레플리카/집계 스토어 · 컬럼 지향 |
| 44 | 이력 있는 마스터 | 덮어쓰면 **작년 매출이 오늘 가격으로 재계산** · 변경마다 새 행 + 유효 기간 · 거래 시점 값 참조 · 이력 필요한 속성만 ✅`DB-20` |
| 45 | 멀티테넌트 격리 | DB/스키마/테넌트 ID 컬럼 · 마지막의 위험 = **조건 누락 → 타 테넌트 노출** · **RLS 로 DB 쪽에서 강제** ✅`DB-13` |
| 46 | 개인정보 | 암호화·접근 제어 · **갖지 않고 빨리 지운다** · 개발 환경은 마스킹 · 로그 금지 · 복제본 위치 파악(백업·분석·캐시) |
| 47 | 배치 도중 실패 | 체크포인트 → 실패 덩어리부터 재개 · 각 덩어리 멱등 · 실패 건 따로 보관 · 멈출지 건너뛸지는 업무 요건 |
| 48 | 배치 이중 실행 방지 | 행 락/락 테이블/Redis 락으로 **한 노드만 실행권** · 유효 기간(노드 죽어도 영원히 안 잡힘) · 만료 후 뒤늦은 처리 대비 멱등 |
| 49 | 서버리스 → DB | **동시 실행 수가 그대로 접속 수** · 1000 함수 = 1000 접속 → DB 가 거절 · 프록시 중개 / 동시 실행 상한 ✅`DB-25` |
| 50 | 운영 DB 가 갑자기 느려지면 | **전부 느린가, 특정 쿼리만인가** · 리소스·락 vs 실행 계획 변화 · 실행 중 쿼리·대기 이벤트·락 의존 · 최근 배포와 대조 · **즉시 대처와 재발 방지를 나눠 말하기** |

1. **매일 아침 5분** — 그날 학습할 6문항의 키워드만 훑기
2. **학습 중** — 키워드만 보고 일본어로 말하기 → 녹음 → [`Part1`](../db-면접/Part1.md)·[`Part2`](../db-면접/Part2.md) 원문 대조
3. **✅ 문항은 한 번은 돌려 본다** — `./gradlew test -Dverify.only=DB-14` 처럼. 되물었을 때 답할 수 있는 범위가 달라진다
4. **면접 전날** — 함정 8개 + S급 10문항 키워드만
5. **면접 당일** — [`필수-키노트`](../db-면접/필수-키노트.md) 의 **일본어 한 문장 10개** + "여섯 개의 아니오"
